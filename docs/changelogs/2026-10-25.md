# Changes — October 25, 2026

## Super admin dashboard

Anna paid $50 through Stripe on Oct 24 (pi_3UU56lFGZjGqoSIX0GHzSAsU, succeeded), but the banner stayed and no payment showed in her history, so the webhook likely never wrote the row. Root cause is deferred until Henry can capture network logs with her next month. Meanwhile, this adds a way to mark accounts current by hand.

- New `users.is_super_admin` and `users.must_change_password` columns (`lib/migrate.ts`).
- `/admin` (`app/admin/`): lists every user with paid-through date, Current/Overdue, auto-pay status, and payment rows. Per user: **Record payment** (type, amount, months, optional start date, optional Stripe ID) and **Delete** per row. With no start date, it begins when the current period ends (or now), the same rule as the webhook. With a Stripe ID, a later webhook for that payment is a no-op. Without one, the reference is `manual_<uuid>`. Non-admins get a 404 (`lib/admin.ts` → `requireSuperAdmin`).
- Admins see **Admin** in the account menu instead of Payments, get no banner, and `/payments` redirects them to `/admin`.
- First-login password change: login puts a `mustChangePassword` claim in the JWT when the flag is set. `proxy.ts` sends that session only to `/set-password` (API calls get 403) until a new password is saved, which clears the flag and reissues the cookie.
- Payment history labels `manual` rows as "Manual".
- Tested locally with signed session tokens: temp-password session is confined to /set-password, admin sees /admin and no banner, Anna gets 404 on /admin and still sees her banner. The insert SQL was tested directly: a duplicate Stripe ID is rejected, and a custom start date plus 2 months works. Test rows were deleted.
