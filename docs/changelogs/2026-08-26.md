# Changes — August 26, 2026

## Sticky header while reading (not just while editing)

- Anna emailed: "please add Edit button the way you added Save. So that I can choose Edit or Save at any point during reading." The entity detail header was only pinned (`position: sticky`) while in edit mode (see July 28 changelog), so the Edit button scrolled out of view while just reading a long entry.
- Made the header sticky in both view and edit mode in `components/EntityDetailClient.tsx`, so Edit (and Download PDF / Duplicate) stay reachable at any scroll position while reading, matching how Save/Cancel already behave while editing.
- Single shared detail-page component, so this applies to all seven entity types.

No DB changes.

## CE fields: drop Topic, add Faculty/Content/Date/CE/Cost

- Anna sent a mockup of the CE edit form marking up the desired field changes: remove Topic, and add Faculty, Content, Date, CE, and Cost, in that order relative to the existing Source field.
- Updated the `ce` entity's field list in `lib/entities.ts` to: Description, Faculty, Content, Source, Date, CE, Cost, Notes (Topic removed from the form).
- DB: added `faculty`, `content`, `date`, `ce`, `cost` text columns to the `ce` table via `lib/migrate.ts` (`npm run migrate`, applied locally). Left the existing `topic` column in place (unused by the UI now, but not dropped, so any existing data isn't lost).

```sql
ALTER TABLE ce ADD COLUMN IF NOT EXISTS faculty TEXT;
ALTER TABLE ce ADD COLUMN IF NOT EXISTS content TEXT;
ALTER TABLE ce ADD COLUMN IF NOT EXISTS date TEXT;
ALTER TABLE ce ADD COLUMN IF NOT EXISTS ce TEXT;
ALTER TABLE ce ADD COLUMN IF NOT EXISTS cost TEXT;
```

## Fix: "CE" showing lowercase as "ce" in list page

- Anna pointed out the CE list page showed lowercase "ce" in the item count ("3 ce") and the search placeholder ("Search ce…"), where every other entity type's label reads fine lowercased (e.g. "3 supplements").
- Root cause: `app/[entity]/page.tsx` and `components/EntityListClient.tsx` unconditionally called `.toLowerCase()` on the entity label, which is correct for ordinary words but mangles the "CE" acronym.
- Added `lowerLabel()` in `lib/entities.ts` — lowercases a label unless it's already all-uppercase (an acronym), and switched both call sites to use it. No visual change for any entity except CE, which now reads "CE" in both spots.

No DB changes.

## Source field: text label + link, rendered as a clickable link

- Anna asked (screenshot + email: "Could there be a link to Sources like the link to References?") for the "Source" field to support entering plain text plus a separate link, so it displays as a clickable `<a>` tag rather than raw text.
- `SourceModal`'s "Enter text" mode now has a second input for an optional Link (URL) alongside the text label. `SourceValue`'s `text` variant gained an optional `url` field (`components/SourceModal.tsx`).
- Display: when a source has a `url`, it now renders as a clickable link (label text, or the URL itself if no label was given) instead of plain text — in `components/EntityDetailClient.tsx`.
- Also auto-linkifies existing plain-text sources that are themselves a bare `http(s)://` URL (like the CE example Anna showed), so old entries become clickable without needing to be re-entered.
- Applies everywhere the `entity_source` field type is used: Affiliations, CE, Equipment, and Labs (`lib/entities.ts`).

No DB changes — `source` is still stored as a single TEXT column holding a JSON blob (`{type, text, url}` or `{type, entity_type, entity_id, name}`), unchanged from before.
