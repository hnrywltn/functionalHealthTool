# Changes — October 21, 2026

## Add login (email + password auth)

- The site had no auth at all — every page and API route was open to anyone who could reach it. Added a single-user login for Anna (username is her email, `annastone@me.com`).
- `proxy.ts` (Next 16's rename of `middleware.ts`) runs on every request except `_next/static`, `_next/image` and `favicon.ico`. Without a valid session, pages redirect to `/login?next=<original path>` and `/api/*` returns `401 {"error":"Unauthorized"}`. Visiting `/login` while signed in redirects to `/`.
- `lib/session.ts` — sessions are an HS256 JWT (via the already-installed `jose`) in an httpOnly, `sameSite=lax` `session` cookie (`secure` in production), valid 30 days. Signed with a new `SESSION_SECRET` env var, generated and added to `.env.local`. Stateless: rotating the secret signs everyone out.
- `app/login/` — login page styled to match the home page, plus `login` / `logout` server actions. Passwords are checked with `bcryptjs` (already installed). Email matching is case-insensitive. A wrong email and a wrong password give the same "Incorrect email or password." message, and the check takes the same time either way, so the form doesn't reveal which emails exist. After login, the user goes back to the page they originally requested (only same-site paths are allowed as the `next` target).
- Sidebar: added a "Sign out" button at the bottom, and the sidebar is hidden on `/login`.
- New `npm run set-password -- <email>` script (`lib/set-password.ts`) creates the user or resets the password, with a hidden, confirmed prompt (min 8 chars). There's no sign-up or reset-by-email flow; passwords are set from the command line only.
- Tested locally with a throwaway user (since deleted): unauthenticated redirect/401, wrong password error, successful login and redirect to the original page, tampered or wrong-key cookies rejected, sign out clears the session.
- Updated `docs/tech-stack/` (architecture, api, npm-packages, README) and `CLAUDE.md` to describe the auth layer instead of "no auth".

DB: new `users` table via `lib/migrate.ts` (`npm run migrate`, applied locally). Anna's account (`annastone@me.com`) created in the local DB and verified by signing in through the login form. Reset her password with `npm run set-password -- annastone@me.com`.

```sql
CREATE TABLE IF NOT EXISTS users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

Deploy notes: set `SESSION_SECRET` in production (the app errors without it), run `npm run migrate` against the production DB, then `npm run set-password` there. No login rate limiting yet.
