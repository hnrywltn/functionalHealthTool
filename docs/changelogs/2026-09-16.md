# Changes — September 16, 2026

## Source field: support multiple links, rendered as separate list items

- Anna reported (screenshot annotations on the CE "OCD Intensive Training" entry) that the Source field only holds one text/link pair, so entering several sources for one entry meant cramming multiple URLs into the single Link input. That collapsed on save into one run-on blob (all the URLs concatenated), and since the whole blob started with `https://`, it got auto-linkified as one broken `<a>` tag — clicking it tried to open every link at once and errored.
- `SourceValue`'s `text` variant now holds `links: { text: string; url?: string }[]` instead of a single `text`/`url` pair. `SourceModal` lets you add/remove as many label+link rows as needed ("+ Add another link").
- Display in `EntityDetailClient.tsx` now renders each link on its own line, each auto-linkified independently if it has a URL (or is itself a bare URL), instead of one merged link.
- `parseSourceValue` still reads the old single text/url shape (and the even older bare-string shape) and wraps it as a one-item `links` array, so existing single-source entries keep working without re-entry.
- Entries that were already corrupted by the multi-URL-in-one-field workaround (like the OCD Intensive Training CE record) aren't auto-repaired — those need a one-time manual re-entry through the new multi-link editor.
- Applies everywhere the `entity_source` field type is used: Affiliations, CE, Equipment, and Labs (`lib/entities.ts`).

No DB changes — `source` is still a single TEXT column holding a JSON blob, now shaped `{type: "text", links: [...]}` or `{type: "entity", ...}`.
